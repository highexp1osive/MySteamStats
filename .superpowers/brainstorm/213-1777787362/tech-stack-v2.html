技术栈重评估 — 开源自托管优先

约束：租用服务器运行一个月 → 停止 → 他人从 GitHub 本地搭建

A

Next.js + Prisma + SQLite + Docker

单体应用，零外部依赖，docker-compose up 即用

优点

  • git clone && docker-compose up 一键启动
  • SQLite 无需额外数据库容器，无连接字符串配置
  • 代码最简单，前后端一体 TypeScript
  • Next.js standalone 模式产出纯 Node 进程
  • 服务器一月到期后，别人零门槛复现

缺点

  • SQLite 并发写入有限制（对这类项目足够了）
  • 单容器部署，无法水平扩展（不需要）
B

Next.js + Prisma + PostgreSQL + Docker Compose

前后端一体 + 独立数据库，docker-compose 双容器

优点

  • PostgreSQL 更可靠，数据持久化更有保障
  • 同样是 docker-compose up 一键启动
  • 生产环境标准方案

缺点

  • 需要同时管理 app + db 两个容器
  • 本地搭建需安装 Docker（A 方案也需）
  • SQLite 对本项目完全够用，PG 有些杀鸡用牛刀
C

FastAPI + SQLite + 纯静态前端 + Docker

Python 后端 API + 静态 HTML/JS 前端

优点

  • Python AI 生态最方便（直接调 DeepSeek SDK）
  • FastAPI 性能好，异步原生支持
  • 前后端彻底分离，各自独立

缺点

  • 需要维护两套代码（前后端类型不同步）
  • 整体代码量比 Next.js 方案多不少
  • 前端需额外处理构建和路由
